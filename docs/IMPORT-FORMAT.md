# 匯入與核對

匯入格式與網站匯出的備份相容。以一個「實際航段」為一筆，轉機需拆段；去回程是兩筆。

```json
{"schema_version":1,"flights":[{"id":"example-1","date":"2020-01-10","from":"TPE","to":"NRT","flight":"","departure":"09:00","arrival":"13:00","status":"unverified","note":"","sources":[{"type":"gmail","label":"訂票確認"}]}]}
```

這是格式示例，並非某一實際班次。日期為出發機場當地日期，時間也為各機場當地時間；跨日抵達可寫 `2020-01-11 06:20`。不做沒有時區資訊的飛行時長估算。

## 狀態

- `unverified`：訂票證據存在，但未確認實際搭乘。過去日期不等於已搭乘。
- `flown`：使用者確認或足夠的搭乘證據。只有這類計入里程／護照。
- `upcoming`：未來訂單。過期後網站列為待核對。
- `cancelled`：取消、退票或已被改票取代的原航段。
- `removed`：使用者移除，可在清單中恢復。

班號、出發／抵達時間不確定時留空，切勿用今日班表倒推歷史班次。航線為大圓示意，非真實飛行軌跡。國家以抵達機場計數，可能包含轉機。

## 本機校驗

將整理結果存成 `data/local/flights.reviewed.json`：

```sh
npm run import:prepare -- data/local/flights.reviewed.json
```

輸出 `data/local/prepared-import/flights.json`、`report.json`、`seed.sql`，不會變更任何資料庫或網站。相同日期／機場／班號且欄位相同的航段去重；同航段取消狀態或時間衝突會停止，請先核對改票鏈。缺班號與有班號的兩筆不會擅自合併；跨機場改票也需人工核對。

程式檢查日期、機場、班號及時間格式；移除郵件 URL、主旨、備註、原始 ID 和額外欄位，使用航段雜湊產生穩定 ID。這是減少誤公開的措施，不能取代你逐項查看輸出的確認。票價留在獨立的 `data/local/prices.private.json`；勿把整張訂單金額當成各航段票價。

第一次在網頁用「更多功能 → 還原備份到此瀏覽器」選 `flights.json`。核對後可匯出新備份；輸出檔案仍應只存在本機。瀏覽器還原是整份取代，非自動合併。

若要發布你的飛行紀錄，請依 SELF-HOST.md 將已核對資料準備成新輸出資料夾，再匯入遠端。SQL 僅初始化空來源，絕不覆蓋非空資料庫。既有遠端資料更新需先備份並另行審核。
